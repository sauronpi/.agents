# Markdown 文档

## 工作流程

1. 根据用户请求和现有上下文确定目标文件和范围，并判断任务属于创建、修改还是审阅。仅要求审阅时
   默认只读；用户明确要求变更时，按其范围执行。
2. 读取目标文件和适用的项目规则；按任务需要查看相关文档、Markdown lint 配置及已有验证脚本。
3. 依次遵循用户要求、项目规则与配置、现有文档风格；不要把某个项目的约定当作通用规则。
4. 创建文档时根据用途和目标读者组织内容；修改文档时只处理请求范围，保留原有语义、结构和无关格式。
5. 优先运行项目已有的验证命令；否则使用环境中已有的 `markdownlint-cli2` 或 `markdownlint` 检查受影响文件。没有可用 linter 时，人工检查标题层级、列表和代码围栏。使用项目已有检查或人工核对受影响的相对链接和资源引用。不要仅为验证而新增依赖或配置。
6. 修改任务中，修复本次变更新增的问题并重新验证，不顺带修复无关的既有问题。

## 交付要求

- 概述创建、修改或发现的内容；审阅发现须说明问题、位置和依据。
- 报告实际运行的验证命令及结果。
- 明确说明未执行的验证、剩余风险，并单独列出无关的既有问题。
