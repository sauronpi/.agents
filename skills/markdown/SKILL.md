# Markdown 文档

## 工作流程

1. 判断任务属于创建、修改还是审阅，并确认目标文件和范围。审阅默认只读，除非用户明确要求修复。
2. 读取目标文件、同目录相关文档、项目说明、Markdown lint 配置和已有验证脚本。
3. 依次遵循用户要求、项目规则与配置、现有文档风格；不要把某个项目的约定当作通用规则。
4. 创建文档时根据用途和目标读者组织内容；修改文档时只处理请求范围，保留原有语义、结构和无关格式。
5. 优先运行项目已有的验证命令；否则使用环境中已有的 `markdownlint-cli2` 或 `markdownlint` 检查受影响文件。不要仅为验证而新增依赖或配置。
6. 修改任务中，修复本次变更新增的问题并重新验证；将无关的既有问题单独报告。审阅任务中，只报告问题、位置和依据，不直接修复。
7. 没有可用 linter 时，人工检查标题层级、列表、代码围栏和链接，并明确说明未运行自动验证。

## 交付要求

- 概述创建、修改或发现的内容。
- 报告实际运行的验证命令及结果。
- 明确说明未执行的验证、既有问题和剩余风险。
