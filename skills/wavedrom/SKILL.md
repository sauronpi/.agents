# WaveDrom

使用 WaveDrom 表达数字信号随时间的状态，并让源代码在目标渲染环境中可验证、可审查和可维护。

## 与 Mermaid 的选择边界

- bit-level 波形、采样边沿、位槽、总线字段和事务时序：使用 WaveDrom。
- 软件流程、调用关系、状态转移和模块结构：使用 Mermaid。

## 工作流程

1. 根据用户请求和现有上下文区分创建、修复和审查，并确定图的目标与精度。仅要求审查时
   默认只读；用户明确要求变更时，按其范围执行。
   - 区分单比特时序、串行帧、多位总线事务、连续波形和概念性示意。
   - 确认图用于讲解、协议审查、实现核对还是发布。
2. 确认目标渲染入口。
   - 仅在目标 Markdown 渲染器明确支持时使用 `wavedrom` 围栏。
   - 发布或自动化场景优先保留 WaveJSON/JSON5 源文件并生成 SVG。
   - 需要具体渲染命令、HTML 集成或语法细节时，查看[常用语法参考](references/syntax-reference.md)。
3. 收集会影响语义的事实。
   - 根据图类型确认信号角色、空闲电平、有效窗口、边沿、位序、字段顺序、阶段和时间尺度。
   - 不猜测协议或器件参数；先从用户提供的资料、目标代码、协议规范和邻近上下文核实。未知标记仍能满足讲解或占位目的时继续；若任务要求精确核对或可实现的时序，且缺失信息会改变关键电平、边沿、位序、字段或时间尺度时，再向用户询问。
4. 创建图时先画仅含必要信号的最小图，再按需增加分组、节点、箭头、刻度和说明。
5. 按图类型应用对应规则，不把串行帧要求套用到所有波形。
6. 按“验证”执行适用的检查与渲染，并在需要时核对实现；无法渲染时按该节的降级方式交付。

## 编码规则

### 所有图

- 单比特信号使用 `0`、`1` 表达确定电平；`x` 表示未定义或未知，高阻使用 `z`。WaveDrom 没有独立的 don’t-care token；需要区分时用标注或正文说明，不要只依赖 `x` 的图形。
- 多位总线使用 `=` 或 `2` 至 `9` 表达数据区段，并用 `data` 标注已知值或字段名。
- 使用 `.` 延续前一状态；使用 `|` 添加间隔时，核对它对时间轴和刻度的影响。
- 时钟使用 `p`、`n`、`P`、`N` 等时钟 token；需要时再使用 `period` 和 `phase` 表达比例或偏移。
- 不以原始 `wave` 字符串长度判断对齐。应综合 `period`、`phase`、间隔和子周期检查最终时间位置。
- 只有协议或接口确实存在控制线、方向切换或三态时才添加；不要为满足模板虚构信号。

### 串行位流或帧

- 图用于逐位审查时，确保位槽可明确定位、字段边界与有效位槽对齐；现有标注不足时再增加 `Slot` 或 `Bit slot` 行。
- 显示适用的采样规则，例如采样边沿、位中心或 SPI 的 CPOL/CPHA。
- 事务边界是图的重点时，显示相关控制信号从空闲到有效再回到空闲。
- 字段较多或用户要求逐项核对时，在图后补字段、槽位和值的映射表。

### 多位总线或多阶段事务

- 标出命令、地址、数据、读写等实际存在的阶段及切换条件。
- `data` 标签应与计划标注的数据区段逐项对应。
- 只有总线语义需要时才显示方向、使能、应答和高阻窗口。

### GPIO、PWM 与连续波形

- 根据目标标出频率、周期、占空比、脉宽或关键边沿。
- 只有存在离散字段时才增加位槽或字段映射表。
- 图只表达局部窗口时，说明窗口边界，不强行补成帧事务。

## 标注策略

- 采样关系可用独立信号、`node`、`edge` 或简短图内文字表达。
- 多阶段事务优先用分组、数据标签或间隔区分，不要同时堆叠过多特性。
- 图中只标注理解或核对所必需的信息；正文只解释图中重要且不直观的行为。
- 大型时序拆成多个主题图，避免通过无限增加 `hscale` 维持单图。

## 验证

创建或修复图时，优先在目标环境实际渲染；审查时仅在结论依赖布局、解析或目标兼容性时渲染。
无法实际渲染时，执行可完成的静态与语义检查，并说明未执行渲染的原因和检查缺口；创建或修复时仍交付源码，审查时不重复已有源码。
不将源码标记为已通过渲染验证；依赖渲染结果的结论保留为待确认。

### 语法层

- 实际渲染时，确认没有解析错误、裁切和错位。
- 检查每个计划标注的数据区段都取得正确的 `data` 标签。
- 使用 `node` 和 `edge` 时，检查节点位置、名称和连线目标。
- 检查分组、`period`、`phase`、间隔、刻度与最终时间轴是否一致。

### 语义层

- 对照用户提供的协议规范、器件手册或真值表核对电平、边沿、位序、字段和阶段。
- 区分“未知值”“无关值”“高阻”和“已知总线值”，不要只因图形相似而混用 token。
- 无法从来源确认的行为显式列为假设，不伪装成协议事实。

### 实现层

- 用户要求与代码一致时，再对照驱动、RTL、测试或逻辑分析结果核对。
- 实现与规范不一致时分别说明，不通过修改图隐藏差异。

## 输出要求

- 创建或修复时提供适合目标环境的可渲染源代码，并说明必要的渲染前提；审查时报告问题位置、依据及最小修复建议。
- 报告实际执行的检查及结果、未执行项和剩余限制。
- 简要列出会影响图义的假设或未确认参数。
- 只在逐位审查、复杂字段映射或用户明确要求时附映射表。
- 修复已有图时保留不相关的命名、布局和标注风格。
