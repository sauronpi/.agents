# 第一性原理分析

## 使用边界

仅在用户明确要求使用第一性原理，或主动选择此 Skill 时使用以下方法。普通任务类型、
讨论或审阅此 Skill 本身都不构成启用请求。它不代替领域知识、可靠证据或必须遵守的标准。

## 按需选用的分析指导

根据问题的风险、不确定性和复杂度选择分析深度，分解到足以支持当前判断即可。
以下是可选指导，不是固定顺序、必做步骤或输出栏目：

- 区分有证据支持的事实、基于事实的推断、尚未验证的假设和经验惯例。关键事实缺失或约束冲突时，
  指出缺口及其影响，不编造前提；只提出影响取舍的必要问题或验证办法。
- 从当前目标识别必须满足的基本约束，区分不可改变的限制与可调整的偏好、历史做法；
  不把惯例当作必然，也不在没有依据时把关键约束当作可放弃的假设。
- 在满足目标和约束的方案中选择最简单可行、易验证和维护的方案。公平评估已有方案，
  已满足已验证约束时不为原创性推翻它；第一性原理不等于从零重写。
  不无依据增加功能、抽象或防御性代码，也不为简单而牺牲正确性、安全性、合规性或关键需求。
- 检查关键假设改变时结论是否仍成立，比较重要取舍及成本、风险是否被转移。
  用与问题相称的测试、实验、测量或权威来源验证关键判断；无法验证时说明结论成立的条件。

## 输出

只给出对当前任务有用的结论、必要依据、关键假设、取舍与限制，不要求或展示内部推理过程。
不规定思考长度、Token 预算或模型专属技巧，不因启用此方法扩大任务范围。
