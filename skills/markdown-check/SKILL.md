# Markdown 检查

## 工作流程

1. 确定目标 Markdown 文件范围及任务类型（创建、修改或仅检查）。仅要求检查时默认只读；任务包含创建或修改时按范围执行。
2. 查看适用的项目规则、Markdown lint 配置（如 `.markdownlint-cli2.jsonc`、`.markdownlint.jsonc`）及已有验证脚本；不把某个项目的约定当作通用规则。
3. 执行受影响内容的格式检查：
   - 优先运行项目已有的验证命令；否则使用环境中已有的 `markdownlint-cli2` 或 `markdownlint` 检查受影响文件。
   - 没有可用 linter 时，人工检查标题层级、列表和代码围栏。
   - 不要仅为验证而新增依赖或配置。
4. 使用项目已有检查或人工核对受影响的相对链接和资源引用。
5. 已有等价检查结果在相关内容、配置和环境未改变且覆盖当前要求时可复用，无需重复执行；结果失效或覆盖不足时补充检查。格式检查不能替代语义判断，语义判断也不能冒充格式验证。
6. 修改任务中，只修复本次变更新增的问题并重新验证，不顺带修复无关的既有问题。

## 交付要求

- 报告实际运行的验证命令及结果；检查发现须说明问题、位置和依据。
- 明确说明未执行的验证、剩余风险，并单独列出无关的既有问题。
