# 选择 C# 语法与 .NET API

1. 从项目目录确认构建实际选用的 SDK（包括 `global.json` 的约束），读取项目文件及导入的构建属性。按每个目标框架（TFM）和相关构建条件确认生效的 `LangVersion`；未设时按[微软语言版本说明](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/configure-language-version)判断 TFM 对应的默认值。不要把机器上最新的编译器当作项目配置，也不要用 `LangVersion=latest` 绕过限制。
2. 对语法，核对它首次稳定发布的语言版本、所需的运行时或库支持，以及在当前上下文是否保持原有语义。对 API，另查每个 TFM 的引用程序集和已解析的包是否提供所需成员及重载；语言版本足够不能证明 API 可用。
3. 在满足需求且所有相关目标支持的写法中，优先当前稳定、官方推荐的方案，区分正式版与预览文档。只有部分目标支持新 API 时，优先采用语义等价的共用实现；确有分目标使用的收益时，隔离调用，并为其余目标提供等价路径。
4. 选用兼容写法时，指出具体受限的语法、目标或行为，而不是诉诸团队习惯、旧示例或熟悉程度。不为展示新写法升级 SDK、依赖或重构无关代码。实现后按项目原有方式构建所有受影响的 TFM，并用相关测试核对行为。
